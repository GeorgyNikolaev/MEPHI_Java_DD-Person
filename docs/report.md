## 1. Введение

Настольные ролевые игры, в частности Dungeons & Dragons (D&D), предполагают детальное описание персонажей — внешности, роли, атмосферы мира. Создание визуального образа (портрета) традиционно требует навыков рисования или поиска готовых иллюстраций, что занимает время и не всегда соответствует замыслу игрока.

В последние годы языковые модели с поддержкой генерации изображений открывают возможность автоматического создания иллюстраций по текстовому описанию. API GigaChat позволяет интегрировать такую генерацию в прикладные системы.

**DD Person** — веб-приложение для генерации портретов персонажей D&D. Пользователь задаёт описание, роль (архетип), стиль игровой вселенной и эмоциональные параметры; система формирует промпт, отправляет запрос в GigaChat и сохраняет результат. Реализованы авторизация, история генераций, шаблоны персонажей и избранное.

Проект построен как клиент–серверное приложение: backend на Java (Spring Boot), frontend на React, хранение данных в PostgreSQL, вспомогательные задачи — в Redis. Разработка и демонстрация рассчитаны на локальный запуск (localhost).

## 2. Цель и задачи работы

### Цель

Разработать веб-систему для генерации и управления портретами персонажей D&D с интеграцией GigaChat API, обеспечивающую безопасную работу пользователей, сохранение истории и повторное использование параметров персонажа.

### Задачи

1. Спроектировать архитектуру клиент–серверного приложения с разделением слоёв.
2. Реализовать REST API и авторизацию (JWT в HttpOnly cookies).
3. Интегрировать GigaChat: OAuth, chat/completions, получение и сохранение изображений.
4. Реализовать модуль сборки промптов на основе параметров пользователя (без ручного ввода промпта в UI).
5. Обеспечить асинхронную обработку длительных запросов генерации.
6. Реализовать хранение данных в PostgreSQL и вспомогательную логику в Redis.
7. Разработать клиентский интерфейс (React) для всех основных сценариев.
8. Подготовить документацию, тесты и инструкцию запуска.

### Актуальность

Автоматизация создания визуальных образов снижает порог входа для игроков и мастеров, а модульная архитектура с выделенным слоем интеграции демонстрирует применение современных практик разработки на Java.

## 3. Проделанная работа

Работа выполнялась поэтапно:

**Этап 1 — архитектура и каркас.** Спроектирована структура monorepo (backend + frontend), описана архитектура, настроен Docker Compose для PostgreSQL и Redis.

**Этап 2 — backend foundation.** Spring Boot 3.4, Java 21, JPA-сущности (8 таблиц), репозитории, enums с русскими подписями, i18n, глобальная обработка ошибок.

**Этап 3 — авторизация и API.** Регистрация, login, refresh, logout; JWT в cookies; Swagger UI; Spring Security.

**Этап 4 — генерация и GigaChat.** Модуль промптов (Strategy + Builder), клиент GigaChat, асинхронный pipeline, rate limiting, аудит вызовов API, хранение JPG на диске.

**Этап 5 — персонажи и избранное.** CRUD шаблонов персонажей, генерация по шаблону, добавление портретов в избранное.

**Этап 6 — frontend.** React SPA: авторизация, форма генерации, история, персонажи, избранное, polling статуса генерации.

**Этап 7 — финализация.** Executable JAR, скрипты запуска (`run.bat`, `run.sh`), unit- и integration-тесты, документация в `docs/`, рефакторинг дублирования кода, улучшение сообщений об ошибках на клиенте.

## 4. Дополнительный функционал

### Асинхронная генерация

Вызов GigaChat может занимать десятки секунд. Синхронный HTTP-запрос привёл бы к таймаутам и плохому UX.

**Решение:** при `POST /generations` запись сохраняется со статусом `PENDING` и сразу возвращается клиенту (HTTP 202). После commit транзакции публикуется событие `GenerationRequestedEvent`; listener в отдельном потоке (`@Async`) запускает `ImageGenerationPipeline`: статус `PROCESSING` → вызов GigaChat → `COMPLETED` или `FAILED`. Frontend опрашивает `GET /generations/{id}` до завершения.

### Rate limiting через Redis

Для защиты от злоупотребления API GigaChat и контроля нагрузки реализован `GenerationRateLimitService`: счётчики запросов на пользователя в Redis (лимиты в час и в сутки, настраиваются в `application.yml`). При превышении — HTTP 429 с сообщением на русском (i18n).

### Прочее

- **Аудит GigaChat** — таблица `gigachat_api_calls` с HTTP-статусом, длительностью и учётом токенов.
- **Кэш OAuth-токена GigaChat** в Redis — меньше обращений к серверу авторизации.
- **Blacklist refresh-токенов** в Redis при logout.
- **Шаблоны персонажей** — повторная генерация без повторного ввода параметров.
- **Избранное** — сохранение понравившихся портретов без привязки к «кампаниям».

## 5. Паттерны проектирования

| Паттерн | Где | Зачем |
|---------|-----|-------|
| **Strategy** | `generation/prompt/strategy/*` | Каждый аспект промпта (вселенная, роль, настроение, тон) — отдельный класс. Легко добавлять новые параметры без разрастания `if-else`. |
| **Builder** | `PromptBuilder` | Собирает итоговый system/user промпт из набора стратегий. |
| **Port / Adapter** | `ImageGenerationPort`, `GigaChatImageAdapter` | Изолирует бизнес-логику от GigaChat API; замена провайдера не затрагивает pipeline. |
| **Repository** | Spring Data JPA | Абстракция доступа к PostgreSQL; декларативные запросы вместо ручного SQL в сервисах. |
| **DTO + Mapper** | `api/dto`, `api/mapper` | Отделение HTTP-модели от JPA-сущностей; enums с `labelRu` для UI. |
| **Event-driven (Observer)** | `GenerationRequestedEvent` + `@TransactionalEventListener` | Запуск async pipeline строго после commit — данные консистентны. |
| **Layered architecture** | api → service → persistence | Разделение транспорта, сценариев и данных. |

Паттерны выбраны не «для галочки», а там, где они снижают связность: GigaChat может меняться, промпт-логика расширяется, генерация не блокирует HTTP-поток.

## 6. Стек технологий и запуск

### Стек

| Слой | Технологии |
|------|------------|
| Backend | Java 21, Spring Boot 3.4, Spring Security, Spring Data JPA, WebFlux (GigaChat) |
| БД | PostgreSQL 16 (Hibernate `ddl-auto: update`) |
| Кэш / лимиты | Redis 7 |
| Frontend | React 19, TypeScript, Vite 7, React Router |
| API-документация | Swagger (springdoc-openapi) |
| Сборка | Maven → JAR; npm (frontend) |
| Инфраструктура | Docker Compose |

### Запуск

```bash
docker compose up -d
cp backend/.env.example backend/.env   # GIGACHAT_AUTH_KEY, JWT_SECRET

cd backend && mvn spring-boot:run      # или ./run.sh (macOS)
cd frontend && npm install && npm run dev
```

- Backend: http://localhost:8080  
- Swagger: http://localhost:8080/swagger-ui.html  
- Frontend: http://localhost:5173  

Подробно: [launch.md](launch.md), [stack.md](stack.md).

## 7. Заключение

В рамках работы разработана веб-система **DD Person** для генерации портретов персонажей D&D через GigaChat. Реализован полный цикл: регистрация и авторизация, создание запроса на генерацию, асинхронная обработка, просмотр результата, история, шаблоны персонажей и избранное.

Применены современные подходы: REST API, JWT в HttpOnly cookies, ORM (JPA/Hibernate), асинхронная обработка, rate limiting через Redis, модульная сборка промптов и изоляция внешнего API через порт/адаптер. Клиентская часть предоставляет формы параметров на русском языке без необходимости редактировать промпт вручную.

Поставленная цель достигнута. Система работает на localhost, документирована и покрыта автоматическими тестами. В перспективе возможны: миграции БД (Flyway), планировщик очистки старых файлов, деплой на сервер — для учебного проекта это не требовалось.
