# Сценарии использования

## UC-1: Регистрация и вход

**Актор:** новый пользователь  
**Цель:** получить доступ к генерации портретов

1. Пользователь открывает `/register`, вводит email, пароль, имя.
2. Backend создаёт запись в `users`.
3. Frontend выполняет login, получает JWT в HttpOnly cookies.
4. Пользователь попадает на `/dashboard`.

**Результат:** аутентифицированная сессия без хранения токена в localStorage.

---

## UC-2: Генерация портрета «с нуля»

**Актор:** авторизованный пользователь  
**Цель:** получить JPG портрета по описанию и параметрам

1. Пользователь на `/generate` заполняет описание, роль, вселенную, настроение, шкалы.
2. `POST /api/v1/generations` → проверка лимита (Redis), запись `PENDING`, промпт собран на сервере.
3. Асинхронный pipeline вызывает GigaChat, сохраняет JPG.
4. UI polling показывает статус и изображение.
5. При ошибке — `FAILED`, доступен retry.

**Результат:** портрет в `portrait_artifacts` + файл в `storage/portraits/`.

---

## UC-3: Шаблон персонажа и повторная генерация

**Актор:** авторизованный пользователь  
**Цель:** не вводить параметры заново при новом портрете

1. Пользователь создаёт персонажа на `/characters` (имя + параметры) или сохраняет генерацию как персонажа (UC-6).
2. На странице персонажа нажимает «Сгенерировать портрет».
3. `POST /api/v1/characters/{id}/generations` — параметры берутся из шаблона.
4. Запрос получает `character_id` (служебно, для async pipeline).
5. После успеха обновляется `characters.last_portrait_id`.

**Результат:** новый `generation_request` в истории; у персонажа обновлён последний портрет.

---

## UC-4: Избранное

**Актор:** авторизованный пользователь  
**Цель:** сохранить понравившийся результат генерации

1. На странице результата генерации — «В избранное».
2. `POST /api/v1/portraits/{id}/favorite` → запись в `favorite_portraits`.
3. Список на `/favorites`: портрет, описание, роль, вселенная, дата добавления.
4. Клик по карточке открывает `/generations/{id}`.
5. Удаление — `DELETE /api/v1/portraits/{id}/favorite`.

**Результат:** избранные портреты без привязки к шаблонам персонажей.

---

## UC-5: История, повтор и удаление

**Актор:** авторизованный пользователь  
**Цель:** просмотреть прошлые попытки, повторить или удалить

1. `/history` — список с фильтром по статусу.
2. Открытие детали — параметры, промпт, портрет или ошибка.
3. При `FAILED` — `POST /api/v1/generations/{id}/retry` с теми же параметрами (новый запрос).
4. `DELETE /api/v1/generations/{id}` — удаляет запрос, портрет, JPG и записи в избранном (включая `PENDING`).

**Результат:** управление историей генераций.

---

## UC-6: Сохранить генерацию как персонажа

**Актор:** авторизованный пользователь  
**Цель:** создать шаблон персонажа из готовой генерации

1. На `/generations/{id}` пользователь нажимает «Сохранить как персонажа», вводит имя.
2. `POST /api/v1/generations/{id}/character` — параметры и портрет копируются в новый `characters`.
3. Генерация остаётся в истории независимо; повторное создание персонажа из той же генерации разрешено.

**Результат:** новый шаблон персонажа с `last_portrait` из генерации.

---

## UC-7: Управление персонажами

**Актор:** авторизованный пользователь  
**Цель:** редактировать и удалять шаблоны

1. `/characters` — список шаблонов.
2. `PUT /api/v1/characters/{id}` — обновление имени и параметров.
3. `DELETE /api/v1/characters/{id}` — удаление шаблона; у связанных генераций `character_id` обнуляется.

**Результат:** CRUD шаблонов без удаления истории генераций.
